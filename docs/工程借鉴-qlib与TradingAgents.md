# 工程借鉴：Qlib、TradingAgents 与 Vibe-Trading

> 调研日期：2026-11-11  
> 目的：借鉴研究工程方法，而非移植交易平台或寻找“AI 炒股策略”。  
> 结论：**拾米应保留现有真实数据、回测和实验目录，补齐数据时点、实验复现、独立确认及 AI 权限边界；暂不整体引入三个框架。**

## 一、项目定位与借鉴边界

| 项目 | 经官方资料确认的能力 | 主要借鉴 | 不建议照搬 |
|---|---|---|---|
| Qlib | 覆盖数据处理、训练、回测、组合分析；`qrun` 配置驱动工作流；Recorder 记录参数、指标和产物；提供数据健康检查及滚动模型管理 | 模块化研究流水线、实验记录、数据健康检查、滚动评估 | 当前引入完整模型库、二进制数据体系、MLflow 和在线训练系统，成本大于收益 |
| TradingAgents | 分析员、牛熊研究员、交易员、风险与组合角色；支持检查点恢复、决策结算、日期网格回测和时点数据约束 | 反方审查、运行恢复、历史决策结算、LLM 非确定性披露 | 把多 Agent 辩论或组合经理批准当作策略有效性与风控证据 |
| Vibe-Trading | 将自然语言问题转成研究报告、可运行回测和模拟组合；保存策略、成交、净值、证据及研究修订版本 | “提问—取数—执行—验证—复盘”闭环、研究版本比较、运行产物可检查 | 自然语言直接生成策略上线、自动扩数据源、接入券商实盘 |

TradingAgents 官方明确说明其是研究脚手架，不是具有固定、可复制收益的策略；LLM 采样和动态新闻都会使同一日期重复运行产生差异。Vibe-Trading 虽支持授权券商和熔断，但这属于应主动排除的能力，而不是拾米当前目标。

## 二、主题一：研究文化——从“证明想法”转为“允许证伪”

### 上游做法

- Qlib 将数据、模型、回测、分析拆成可独立使用的模块，并提供基准工作流。值得借鉴的是统一比较口径，而不是模型数量。
- Qlib Recorder 将一次运行涉及的参数、指标、预测和回测产物关联保存，使实验可以检索和比较。
- TradingAgents 使用牛熊研究员和风险角色进行反向审查；其价值是强制呈现反例，不是通过角色投票提高可信度。
- Vibe-Trading 的研究流程为 Plan、Ground、Execute、Validate、Revisit，强调先确定标的、区间和基准，再取数、回测、检查换手与回撤，最后根据新证据修订结论。

### 拾米落地

1. **实验从假设单开始**：包含问题、证据、唯一变量、预期方向、证伪条件、基准和成本口径；禁止先跑批量参数再补故事。
2. **保留失败实验**：不删除负超额、零交易和回撤恶化结果；报告必须同时展示旧版、新版和沪深300。
3. **复杂度需要证据换门票**：单变量规则未证明有效前，不引入机器学习、多 Agent 或新数据源。
4. **把交易活跃度纳入有效性判断**：零交易窗口可说明避险规则发挥作用，但不能单独证明选股或交易能力。

当前案例尤其值得警惕：最新实验报告中 4/6 窗口正超额、中位超额 1.36pp，但第 2、4、5、6 窗口均为零交易，只有第 1、3 窗口发生交易。因此不能仅凭“正超额窗口过半”宣布达标，应同步披露活跃窗口数、信号数、成交数、仓位暴露和换手率。

## 三、主题二：数据治理——先回答“当时能知道什么”

### 上游做法

- Qlib 明确区分原始行情、表达式特征、预处理器和数据集；学习期与推理期处理器可以不同，减少处理逻辑混用。
- Qlib 数据健康检查覆盖缺失值、必需字段、复权因子及异常跳变；文档还提醒不同数据源的复权价格可能不同。
- TradingAgents 对美国财报按实际申报日期提供历史值， later restatement 不回填到较早运行；无法确定历史公开时点的数据会被拒绝，而非假装可得。
- Vibe-Trading 保存数据来源、日期、证据和运行产物，并支持对同一价格输入重新进行费用、滑点和样本外验证。

### 拾米落地

为每批研究数据建立不可变清单，至少记录：

```text
dataset_id / content_hash
symbol / trade_date / period_end
published_at / available_at / retrieved_at
source / query / adjustment / timezone
universe_snapshot / delisted / historical_ST
quality_status / missing_fields / warnings
```

关键纪律：

- **业务日期不等于可得日期**：财报、公告、新闻、指数成分和 ST 状态必须按当时公开时间截断。
- **缺失不是零**：核心字段缺失、日期非法、重复记录或复权口径冲突时失败关闭，不用零值或另一来源静默补位。
- **股票池也是时点数据**：当前名录回填历史会引入幸存者偏差；现有披露应保留，并逐步补历史上市、退市、ST 和指数成分快照。
- **实验绑定数据快照**：仅记录 Git hash 不足以复现；缓存更新后，同一代码可能得到不同结果。
- **跨源校验不能制造伪精确**：备用源可用于可用性和交叉检查，但字段语义、复权方式或交易日不一致时不得直接拼接。

拾米已经具备真实数据失败关闭、未知值不补零、抓取时间记录等测试，应在此基础上扩展，而不是重建数据层。

## 四、主题三：工程闭环——每次结论都能复现、比较和撤回

建议统一为：

```text
假设登记
  → 冻结代码、参数和数据快照
  → 离线回测与成本敏感性
  → walk-forward 训练/验证
  → 冻结参数后运行独立确认集
  → 保存结果、成交、证据和报告
  → 独立反例验收
  → 本人批准的只读影子观察
  → 灰度或废弃
  → 持续监测与一键回滚
```

现有 `iteration/run_experiment.py` 已设计保存 `experiment.json`、`result.json` 和 `report.md`，并记录参数、Git hash 和数据口径；`test_walk_forward.py` 已覆盖窗口划分、窗口后数据突变不影响前窗、单变量覆盖等契约。这些是正确地基，应继续利用。

下一步最小增量：

1. **统一实验入口**：所有实验必须经过同一运行器，避免不同目录的元数据格式不一致。
2. **补充实验血缘**：记录 `experiment_id`、`parent_id`、假设编号、参数 diff、代码 dirty 状态、依赖版本和数据快照 hash。
3. **补充运行状态**：`RUNNING / FINISHED / FAILED / REJECTED / ARCHIVED`，失败也保留错误和已有产物。
4. **增加比较视图**：只展示新旧版本的假设、参数、逐窗口超额、回撤、成交数和成本差异，不做“收益排行榜”。
5. **设置最终确认集**：参数选择不得查看最终确认集；若现有历史窗口均已反复用于筛选，应把后续新数据作为真正确认集。
6. **影子运行后再灰度**：比较预期信号、实际数据可得性和人工执行偏差，旧版本始终保留。

当前无需引入 Qlib 的存储格式或 MLflow；JSON、成交文件和报告足以支撑现阶段的复现闭环。

## 五、主题四：AI 辅助而非直接交易

### 合适的 AI 工作

- 对已完成交易按入场位置、持有期、市场状态、行业和退出原因聚类。
- 从证据中提出最多三条可证伪假设，并给出建议的单变量修改。
- 读取回测产物，指出样本不足、零交易、成本敏感、窗口不稳定和数据缺口。
- 生成实验报告草稿及正反两方论证，供独立验收人员检查。

### 必须禁止

- 根据一段自然语言分析直接生成买卖指令或修改线上配置。
- 自主遍历参数直到找到“好看”的结果，再把同一窗口称为样本外。
- 用多 Agent 一致意见代替数据证据，或把 Agent 的风险批准当成人审。
- 在无快照、无模型版本、无提示词记录的情况下复用历史 AI 结论。
- 连接券商、持有交易凭证或自主扩大数据与工具权限。

建议 AI 只输出结构化提案：

```json
{
  "hypothesis": "可证伪的一句话",
  "evidence_refs": ["实验及成交记录"],
  "single_change": {"field": "threshold", "from": 30, "to": 35},
  "expected_effect": "减少追高交易",
  "falsification": "活跃窗口不足或样本外超额恶化",
  "validation": ["walk_forward", "cost_sensitivity", "final_holdout"],
  "unknowns": ["历史ST时点偏差"]
}
```

每次 AI 运行还需保存模型提供方、模型版本、温度、提示词版本、输入快照、工具调用、token/费用和输出 hash。低温度不能消除非确定性，因此 AI 文本不是复现依据，结构化提案和冻结数据才是。

## 六、实施优先级

| 优先级 | 动作 | 验收标准 |
|---|---|---|
| P0 | 统一实验清单、数据快照、交易活跃度和成本敏感性 | 任意实验可由另一人从干净环境复现；零交易不能掩盖低样本 |
| P0 | 隔离最终确认集 | 参数选择流程无法读取确认集；确认结果只用于最终验收 |
| P1 | 建立研究结论版本与差异比较 | 能查看结论、证据和参数在两次修订间的变化 |
| P1 | 上线只读单 Agent 假设生成 | 每轮最多三条结构化提案，无线上写权限，全部经工程验证 |
| P2 | 影子运行与滚动复盘 | 预期与实际偏差可追踪，失败自动退回旧版 |
| 冻结 | 多 Agent 自动交易、券商连接、新模型库和大规模数据源扩张 | 在策略有效性与合规专项完成前不启动 |
